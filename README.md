# 九州旅遊助手 2026/09/27–10/05

**已上線：https://ing0001000-jpg.github.io/kyushu-2026/**

手機用 Safari／Chrome 開上面的網址 →「加入主畫面」，桌面會出現⛩️圖示，點開是全螢幕、沒有網址列，離線也能用。

## 兩種版本

**1. 專案版（`index.html`）** — 完整 PWA。用 http/https 開啟時會註冊 Service Worker，把全部檔案 precache 起來，之後真正離線也能開。放到任何靜態主機（Netlify、Vercel、GitHub Pages）都可以直接用。

**2. 單檔版（`dist/kyushu.html`）** — 所有 CSS／JS／資料／圖示 inline 成一個檔案。

```bash
node tools/build-single.js
```

單檔版沒有 Service Worker（Artifact 平台的外層 `<head>` 由平台產生，無法註冊 SW），是「載入後靠瀏覽器快取」的準離線。功能與「加入主畫面」都正常。

> Service Worker 的註冊只在真實瀏覽器裡有效，開發用的內嵌瀏覽器會擋掉 SW 腳本抓取。要驗證離線，請用 Safari／Chrome 開專案版，載入一次後開飛航模式重整。

## 密碼門檻

第一次打開會要求填**名字**和**進入密碼**，通過後記在該台裝置，之後不再問。名字只存在自己手機上，不會回傳給任何人。

密碼在後台的「設定與發布」裡自己設，`data/config.js` 只存 SHA-256 雜湊，看不到密碼原文。要設兩組：

| | 給誰 | 用途 |
|---|---|---|
| 進入密碼 | 全團 6 人 | 打開 App 要輸入 |
| 後台密碼 | 只有你 | 進 `#/admin` 要輸入 |

**這是「擋一下」，不是資安機制。** repo 是公開的（免費帳號開 GitHub Pages 的唯一方式），行程、住宿、電話都以明文放在 `data/*.js` 裡。會看網頁原始碼的人可以完全繞過這道門看到全部內容。它擋得住的是路過隨手點開連結的人，擋不住有心人。網址仍然不要貼到公開社群。

真正要防的話得把資料加密後才上傳（沒有密碼連原始碼都看不出內容），那是另一種做法，需要時再說。

## 後台管理

入口：「資訊」分頁滑到最下面的「後台管理」，或直接開 `#/admin`。

可以改：9 天行程的每個時間軸項目（新增／刪除／上下移）、航班、租車、住宿、費用、收藏地點（改備註、換分區、刪除）、打包清單、行前待辦、指南的美食景點。

**兩段式儲存**，這點很重要：

1. **改了就存成草稿** — 只在你這台裝置生效，其他人看到的還是舊的。App 畫面會立刻套用，可以先自己確認。
2. **按「發布到 GitHub」** — 才會寫回 repo，約 1 分鐘後全團拿到新版。

發布會一併把 `sw.js` 的快取版本號 +1，團員手機的舊快取才會失效 — 這是手動改檔案時最容易忘記的一步。

「丟棄草稿」會把這台裝置還原成線上版。注意：密碼也是存在草稿裡的，設完密碼沒發布就丟棄草稿，密碼會一起消失。**設完密碼請立刻發布。**

### GitHub 權杖

發布需要一組 GitHub 存取權杖，在後台「設定與發布」裡填，存在你這台瀏覽器的 localStorage。

建議用 **Fine-grained personal access token**：

- Repository access：只勾 `kyushu-2026` 這一個
- Permissions → Repository permissions → **Contents: Read and write**
- 設一個到期日

那組權杖等於這個 repo 的鑰匙。手機借人、遺失或換機時，記得到 GitHub 設定頁把它撤銷。

> 忘記後台密碼：清掉瀏覽器對這個網站的資料，或直接在電腦上編輯 `data/config.js` 把 `gate` 的欄位清空，再 push。

## 匯入 Google 地圖收藏

`data/places.js` 是從 Google 地圖的「已儲存清單」匯入的，顯示在「指南」每一區的「我的收藏」，每筆都用座標導航。

```bash
node tools/import-places.js <匯出檔.csv|.json|.geojson|.kml> [--resolve]
```

- 吃 Google 地圖清單匯出的 CSV、Takeout 的 GeoJSON、我的地圖的 KML
- 用座標判斷屬於哪一區（離八個區域錨點最近且 40 公里內），沒座標就退回名稱關鍵字比對，都判不出來的丟進「未分區」
- CSV 匯出常常只有短網址沒座標，加 `--resolve` 會連網展開後再判斷
- **會整個覆蓋 `data/places.js`**，在後台改過的收藏地點會被蓋掉

## 改內容

日常改行程建議直接用後台（上一節）。要在電腦上改檔案的話，所有內容都在 `data/`，改完重整就生效（改單檔版要重跑 `node tools/build-single.js`）：

- `data/trip.js` — 9 天行程、航班、租車、住宿、費用。`map` 欄位放日文地名，導航鈕用 Google Maps 搜尋 URL 帶入，所以不需要經緯度。
- `data/guide.js` — 地區美食景點、實用資訊、日文短句
- `data/packing.js` — 打包清單（`window.PACKING`）與行前待辦（`window.TODOS`）
- `data/places.js` — 從 Google 地圖收藏匯入的地點，由 `tools/import-places.js` 或後台產生
- `data/config.js` — 密碼雜湊與 GitHub repo 設定，由後台產生
- `data/art.js` — 城市印象插畫（9 個場景 + 線性圖示）與路線地圖的畫法，全部是內嵌 SVG，零外部請求。
- `data/geo.js` — 路線地圖資料：12 個地點的真實經緯度、每天跑的順序、九州海岸線。

### 路線地圖

「今天往哪裡跑」出現在每一天的頁面，「路線總覽」出現在行程分頁與出發前的今天頁。

- **地點是真座標**。`GEO.places` 存的是 Google 地圖上查得到的經緯度，投影用等距圓柱＋依緯度壓縮經度（九州取 33.1°N），所以圖上的相對位置、方向與遠近都是對的，別府在海邊、熊本在內陸、長崎在半島上都不會跑掉。
- **海岸線也是真的**。取自國土數值情報的縣界多邊形（dataofjapan/land），用 Douglas–Peucker 簡化到約 1.3 km 精度、裁到畫面範圍，再用同一組投影參數換算成畫布座標。畫的是 7 個縣的多邊形疊起來，所以縣界會淡淡地透出來。要重新產生的話，腳本邏輯記在這一段裡：下載 japan.geojson → 取九州各縣 → 簡化 → 裁切 → 投影 → 存成 `GEO.land` 的 path 字串。
- **每天跑哪裡**寫在 `GEO.route`（第 5 天是熊本出發、繞高千穗與阿蘇再回熊本，所以畫出來是一個三角形）。當天的路線用該地區的點綴色畫粗線加箭頭，其他天用淡虛線當背景，讓人知道今天在整趟裡的哪一段。
- **畫成插畫而不是製圖**：沿著海岸描三層越來越寬的淡邊、被陸地蓋掉內側之後只剩外側，就成了古地圖那種等深線暈染；山區（阿蘇、九重、由布岳、雲仙、祖母、九州山地…）放手繪的小山形，左面亮右面暗；再加上羅盤、25 km 比例尺、海域名與海上的小浪紋。海岸線與山形都套同一組手繪抖動濾鏡，所以邊緣跟插畫是同一種筆觸。
- 地圖配色跟著地區色盤走（`--map-sea` / `--map-land` / `--map-ink` / `--map-edge` / `--map-echo` / `--map-hill`），深色主題會自己換成夜間版的對比。

### 城市印象插畫

每座城市一張，不是地標拼貼：先整理該城市 5–8 個有辨識度的旅行印象（地形季節、建築街道交通、食物植物動物、色彩氣候、實際會遇到的生活場景），再挑其中 3–5 個最能代表城市氣質的，簡化幾何化之後重新構圖。例如福岡是「中洲屋台的暖光 × 河 × 被壓扁的都市天際線 × 放大的紅燈籠」，別府是「屋瓦之間升起的八道湯煙 × 地獄的朱紅與鈷藍」。

風格是 modern folk illustration／editorial travel poster／naive art：大面積平面色塊、明確視覺焦點、前中後景分層、刻意留白，辨識度來自輪廓色彩與象徵物而不是寫實描繪，並且刻意做了比例變化（放大的燈籠與稻穗、縮小成模型的鳥居與辻馬車）。

- **配色**：每座城市一組 6 色的有限色盤，定義在 `app.css` 的 `[data-reg="…"]`：`--c-sky`（紙／天空）、`--c-far`（遠景）、`--c-mid`（中景）、`--c-near`（近景墨色）、`--c-pop`（整張畫唯一的高彩度點綴）、`--c-pale`（光／霧／白牆），另外 `--rb` 是這個地區在 UI 上的主色。深色主題會把同一組色盤換算成「夜間版海報」：紙色壓暗、點綴色反而更亮，構圖不變。
- **質感**：`ART.defs` 裡有兩個手繪抖動濾鏡（`hz-hand` 給大色塊、`hz-hand2` 給細節）讓邊緣像剪紙或蠟筆塗出來的，再加一層 `hz-grain` 顆粒疊在畫面上；整個介面的底也墊了一張紙纖維（`--fiber`）。濾鏡由 `ART.mount()` 在啟動時塞進文件裡，全站共用一份。
- **畫布**：400 × 132（旅遊海報橫幅比例）。焦點要放在 x 140–260，因為指南分頁的小圖章會裁切成中央的正方形。
- **校稿**：`tools/art-preview.html` 會把 9 張並排出來（`?cols=2&only=aso,yufuin` 可放大看指定幾張、`?dark=1` 看夜間版）。

**注意**：打包清單的勾選狀態用 `群組id:項目id` 當 key 存在 localStorage。改文字沒關係，但改 `id` 會讓已勾選的項目變回未勾選。

改版後記得把 `sw.js` 裡的 `CACHE` 版本號 +1，否則使用者的舊快取不會更新。

## 其他

- `tools/make-icons.js` — 用 Node 內建 zlib 產生鳥居圖示 PNG，不需要 `npm install`
- `tools/art-preview.html` — 插畫校稿板，開 `http://localhost:4173/tools/art-preview.html`
- 唯一的外部資源是 Google Fonts 的 Archivo Black（只用在數字與英文標籤，Latin 子集）。離線或載入失敗時自動退回系統字型，不影響任何功能；中文一律使用系統字型，刻意不載 CJK 網頁字型（那會是好幾 MB，離線就毀了）
- 打包勾選、匯率、深淺色偏好存在各自手機的 localStorage，**不會**在團員之間同步
- 行程內容則是全團共用的（存在 repo 裡），透過後台發布同步
- 深淺色會跟隨系統，右上角按鈕可手動切換
